# 翻訳担当者への作業手順

PC用RPG「Avadon: The Black Fortress」のスクリプト本文を日本語に翻訳します。
作業フォルダ: `L:\SteamLibrary\steamapps\common\Avadon The Black Fortress\_jp_mod`（以下 `_jp_mod`）

## 最初に読むもの
1. `_jp_mod\trans\STYLE.md` — 翻訳方針。**すべて守ること。**
2. `_jp_mod\trans\jobs\<担当名>.json` — 担当分の情報
   - `chunks`: 翻訳するチャンク名の一覧（この順に処理する）
   - `glossary`: 対訳表（英語→日本語）。**ここにある語は必ずこの訳を使う。**
   - `voices`: 既に口調が決まっている人物のメモ。**この口調に合わせる。**
   - `known`: 別の場所で訳し済みの、まったく同じ原文とその訳。**原文が完全に一致する unit には、この訳をそのまま使う。**
   - 対訳表と STYLE.md の共通語彙は、**小文字・複数形で出てきても同じ訳にする**（例: bandits → 山賊、ratlings → ラットリング）。
   - STYLE.md の「7. 個別の決定事項」も必ず守る。特に、長さの単位は原文どおり（feet →「フィート」）で、メートルに換算しない。

## 各チャンクの処理
1. `_jp_mod\trans\chunks\<チャンク名>.json` を読む。`units` の各要素:
   - `id`: 番号（出力のキー）
   - `kind`: 種類（STYLE.md の表を参照。`text`=会話ノードの本文/描写、`question`=一行の発言の選択肢、`lib`=テキストライブラリの文、など）
   - `en`: 原文
   - `ctx`（あれば）: 直前のスクリプトのコメント。話し手の名前であることが多い
   - `code`（あれば）: この文字列が使われているスクリプトの文。他の文字列とつながる部品なので、つながり方を考えて訳す
   - `max`（あれば）: 訳文の上限（全角文字数）
   - ファイルの並び順は会話の流れの順です。前後の文脈を読んでから訳すこと。
2. 全 unit を訳し、`_jp_mod\trans\ja\<チャンク名>.json` に UTF-8 の JSON で書く（Write ツール）:
   ```json
   {
   "12": "訳文",
   "13": "訳文",
   "_voices": {"アンドリュー（Andrew）": "一人称「私」、です・ます調、親切で慌て者"}
   }
   ```
   - キーは id の文字列。原文のすべての id を含めること。
   - `_voices` には、このチャンクで台詞のある人物ごとに、名前（日本語と英語）と口調（一人称、文体、性格）を書く。
   - 訳文に `"` と `\` を使わないこと。
3. 検査を実行する（Bash ツール）:
   ```
   cd "/l/SteamLibrary/steamapps/common/Avadon The Black Fortress/_jp_mod" && python -I tools/check_trans.py trans <チャンク名>
   ```
   - `E`（エラー）が出たら、その id の訳を直して書き直し、エラーが0になるまで繰り返す。
   - `W`（警告）の「対訳表の…が使われていない」は、対訳表の訳を使うよう直す。文脈上どうしても使えない場合のみそのままでよい。
   - 「英語のまま」の警告は、訳し忘れなら直す。
4. 次のチャンクへ進む。同じファイルの続きのチャンクでは、前のチャンクで決めた口調・訳語を引き継ぐこと。

## 最後に
すべてのチャンクを終えたら、次を短く報告する:
- 処理したチャンク数と、残ったエラー・警告の数
- 対訳表にない固有名詞で、自分で訳を決めたもの（英語→日本語の一覧）
- 判断に迷った箇所（あれば最大5件）
